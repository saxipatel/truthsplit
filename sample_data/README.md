# Demo data

All of this is **synthetic**.

| File | What it is |
|---|---|
| `manifest.json` | The oracle: each planted discrepancy, the records it affects, and its expected contribution to `delta = right − left`. |
| `finance_ledger_march.csv` | A "ledger export" with problems planted on purpose (scenario B). |

Both files are generated by `backend/app/seed/demo.py` from `backend/app/seed/shop.py`, a pure-Python model of the seeded `shop` source database (`docker/source-db/02-shop.sh`). Expected values therefore come neither from the database nor from the investigation engine. Tests check that the model matches the seeded database row for row, and that these committed files equal a fresh generation.

```bash
make demo-files
```

```bash
make demo
```

The first command regenerates both files. The second loads both scenarios into the running stack; it is safe to repeat.

## Scenario A: fully explained

Finance (`finance_order_revenue`: New York window, net of refunds) vs Sales (`sales_order_payments`: UTC window, orders joined to payments, gross). Expected delta 155,997.39, explained by four confirmed findings:

| Issue | Finding | Contribution |
|---|---|---|
| A1 | Refund treatment | +102,360.14 |
| A2 | Join amplification | +56,224.00 |
| A3 | Cutoff: finance-only orders | −9,604.00 |
| A4 | Cutoff: sales-only orders | +7,017.25 |

The unexplained remainder is 0.00. Fifteen orders belong to two issues at once; the manifest lists them under `overlaps`.
