# Demo data

All of this is **synthetic**.

| File | What it is |
|---|---|
| `manifest.json` | The oracle: each planted discrepancy, the records it affects, and its expected contribution to `delta = right − left`. |
| `finance_ledger_march.csv` | A "ledger export" with problems planted on purpose (scenario B). |
| `settlement_march.csv` | A payment processor's "settlement export" whose amounts are already net of refunds (scenario C). |

All three files are generated by `backend/app/seed/demo.py` from `backend/app/seed/shop.py`, a pure-Python model of the seeded `shop` source database (`docker/source-db/02-shop.sh`). Expected values therefore come neither from the database nor from the investigation engine. Tests check that the model matches the seeded database row for row, and that these committed files equal a fresh generation.

```bash
make demo-files
```

```bash
make demo
```

The first command regenerates the files. The second loads all three scenarios into the running stack; it is safe to repeat.

## Scenario A: fully explained

Finance (`finance_order_revenue`: New York window, net of refunds) vs Sales (`sales_order_payments`: UTC window, orders joined to payments, gross). Expected delta 155,997.39, explained by four confirmed findings:

| Issue | Finding | Contribution |
|---|---|---|
| A1 | Refund treatment | +102,360.14 |
| A2 | Join amplification | +56,224.00 |
| A3 | Cutoff: finance-only orders | −9,604.00 |
| A4 | Cutoff: sales-only orders | +7,017.25 |

The unexplained remainder is 0.00. Fifteen orders belong to two issues at once; the manifest lists them under `overlaps`.

## Scenario B: unexplained remainder

## Scenario C: refunds netted at source

The sales query (orders joined to payments, with the 1:N join declared) against a settlement export that reports each order net of its refund and records the refund. Both sides use the same **gross** definition, so the refund difference sits in the data, not the definitions. Expected delta −159,249.32; unexplained 0.00.

| Issue | What it is | Status | Contribution |
|---|---|---|---|
| C1 | Join copies on the left (244 split-payment orders) | confirmed (`data.join_amplification`) | −56,224.00 |
| C2 | Difference exactly equal to the recorded refund (384 orders) | confirmed (`data.refund_identity`) | −100,479.19 |
| C3 | Keying errors (15 orders); on refunded orders refund + error no longer equals the refund, so the whole difference stays here | confirmed (`data.value_mismatch`) | −2,546.13 |

Ten orders are both split and refunded (C1 and C2), and two split orders also have keying errors (C1 and C3).
